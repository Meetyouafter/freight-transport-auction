# Задача для Claude Code: доработка UI страницы «Активные аукционы»

## Контекст

Проект: Freight Transport Auction, `localhost:5173`. Стек по факту инспекции в браузере: **React + MUI (Material UI)**, роутинг — **TanStack Router**, данные — вероятно **TanStack Query** (виден devtools-виджет), шрифт **Inter**. Найди в репозитории компонент списка аукционов (страница с заголовком «Активные аукционы», карточки с полями «Заявка №», маршрут, даты погрузки/выгрузки, цена, кнопки «Сделать ставку» / «Детали»), компонент фильтров и компонент пагинации — они, скорее всего, лежат рядом или переиспользуются на других страницах.

Ниже — список изменений по итогам UI/UX-аудита, отсортированный по приоритету. Для каждого пункта указаны: текущее состояние (с точными значениями, снятыми через computed styles), что нужно изменить и критерий готовности. Полный аудит с таблицами и обоснованием — в файле `audit-ui-ux.docx` (передан отдельно), этот файл — выжимка в формате технического задания.

Работай по пунктам независимо — каждый можно взять в отдельный PR/коммит. Если для какого-то пункта в кодовой базе уже есть общий MUI `theme` (`createTheme`), меняй токены централизованно там, а не в отдельных компонентах.

## Приоритет 1 — критично

### 1.1 Добавить hover-состояния для кнопок и карточек
Сейчас при наведении на кнопки «Сделать ставку» (`MuiButton-contained`) и «Детали» (`MuiButton-outlined`) не происходит видимых изменений — фон, тень остаются идентичными состоянию без наведения (проверено покадровым сравнением скриншотов до/после hover).

Что сделать:
- Для `MuiButton-contained` (primary, фон `#545333`) добавить hover: затемнение фона на ~8–10% (`theme.palette.primary.dark` или `darken('#545333', 0.1)`), усиление `box-shadow` (elevation 4 вместо 2).
- Для `MuiButton-outlined` добавить hover: лёгкая заливка фона (`rgba(84,83,51,0.08)`), сохранить рамку.
- Добавить `transition: background-color 150ms ease, box-shadow 150ms ease` на оба варианта.
- Если карточка заявки станет кликабельной (см. 3.1) — добавить hover на саму карточку (см. 4.2).

Критерий готовности: наведение курсора на любую кнопку в списке визуально заметно меняет её вид в течение ~150мс.

### 1.2 Визуально разделить селектор размера страницы и номер текущей страницы в пагинации
Компонент пагинации (`MuiPagination`) показывает кнопку текущей страницы «1» (тёмно-оливковый фон `#545333`, белый текст, форма pill) и рядом — селектор количества элементов на странице со значением «10», оформленный **тем же** тёмно-оливковым pill-стилем. Это создаёт впечатление, что «10» — ещё одна страница.

Что сделать:
- Заменить визуальное оформление селектора «на странице» на явный `Select`/`outlined`-компонент, отличный по форме и цвету от `MuiPaginationItem` (например, прямоугольник с рамкой вместо круглой заливной пилюли, нейтральный/белый фон).
- Добавить подпись рядом («Показывать по:») если её ещё нет в DOM (в разметке текст «На странице» присутствует, но стоит проверить, что он не теряется при адаптиве).

Критерий готовности: селектор количества элементов на странице визуально не может быть спутан с кнопкой номера страницы.

### 1.3 Добавить кнопки «Применить» / «Сбросить» в панель фильтров
Панель фильтров (открывается по клику на «Фильтры», раскрывает блок с двумя полями `Номер груза`, `Заказчик`) не содержит явного способа применить или сбросить введённые значения. Непонятно, работает ли фильтрация вживую (debounce) или нужно доп. действие.

Что сделать:
- Добавить кнопку «Применить» (primary, `contained`) и «Сбросить» (`text`/`outlined`) в нижней части панели фильтров.
- Если фильтрация уже реализована как live/debounced — оставить автоприменение, но добавить лёгкий визуальный индикатор применения (например, короткий spinner/подсветка списка на 200–300мс) и кнопку «Сбросить всё».

Критерий готовности: пользователю не нужно гадать, применились ли введённые фильтры.

### 1.4 Расширить набор полей фильтрации
В панели фильтров сейчас только `Номер груза` и `Заказчик` — а в самих карточках отображаются город отправления/назначения, даты погрузки/выгрузки, тип кузова, тип груза. Фильтрации по этим полям нет.

Что сделать (минимальный набор):
- Фильтр по маршруту: `Autocomplete`/`Select` для города отправления и города назначения (можно один комбинированный контрол «откуда → куда»).
- Фильтр по датам: date-range picker для даты погрузки (и, опционально, отдельно для выгрузки).
- Фильтр по типу кузова: `multiselect` (фургон / тентованный / бортовой / и т.д., значения брать из реальных данных).

Критерий готовности: пользователь может отфильтровать список хотя бы по маршруту и диапазону дат погрузки без перезагрузки страницы.

### 1.5 Увеличить контраст карточки к фону страницы
Замер через computed styles: фон страницы `rgb(253,251,212)` (`#FDFBD4`), фон карточки (`MuiPaper-outlined`) `rgb(242,239,196)` (`#F2EFC4`) — контраст между ними **1.11:1** при требовании WCAG 1.4.11 (non-text contrast) для видимых границ UI-компонентов **≥ 3:1**. Граница карточки `rgba(0,0,0,0.12)` тоже практически не видна на этом фоне (контраст ≈1.3:1).

Что сделать (один из вариантов, на выбор дизайнера/фронтенда):
- Вариант А: осветлить/нейтрализовать фон страницы (например, чисто белый или светло-серый `#F7F6F0`), оставив текущий кремовый фон карточки как акцентную поверхность.
- Вариант Б: затемнить фон карточки до контраста ≥3:1 к текущему фону страницы.
- В обоих случаях заменить границу `rgba(0,0,0,0.12)` на более заметную (например, `rgba(84,83,51,0.24)` — на основе основного акцентного цвета) или усилить `box-shadow`.

Критерий готовности: граница карточки и/или разница фонов проходит проверку контраста ≥3:1 (можно проверить через любой WCAG contrast checker).

## Приоритет 2 — средне

### 2.1 Floating label вместо только placeholder в полях фильтра
Поля `Номер груза`, `Заказчик` используют вариант `TextField`, где подпись видна только как placeholder и исчезает при вводе. Сменить на `variant="outlined"` с постоянным floating label, чтобы подпись оставалась видна и при заполненном поле.

### 2.2 Добавить transition для карточки при hover (после реализации 3.1)
Если карточка станет кликабельной целиком — добавить `transition: box-shadow 150-200ms ease` и увеличение elevation на hover, чтобы карточка визуально считывалась как интерактивный элемент.

### 2.3 Сделать карточку кликабельной целиком (или явно показать, что нет)
Сейчас интерактивны только кнопки «Сделать ставку» и «Детали» внутри карточки, сама карточка не реагирует на клик/наведение — это неочевидно пользователю. Либо сделать весь `Paper`-контейнер кликабельным (переход к деталям заявки, `cursor: pointer`), исключая клики непосредственно по кнопкам (`stopPropagation`), либо явно оставить только кнопки интерактивными — тогда убедиться, что нигде в верстке нет намёка на кликабельность всей карточки (никакого `cursor: pointer` на контейнере).

### 2.4 Поднять визуальный вес показателя ₽/км
Значение вида «45.5 ₽/км» под ценой сейчас отрисовано мелким серым текстом — это ключевая метрика для сравнения ставок в аукционе грузоперевозок, её стоит визуально усилить (увеличить `font-size`/`color` или вынести отдельным чипом рядом с ценой).

### 2.5 Визуально различать статус аукциона активен/завершён на уровне карточки
Карточки с бейджем «Победитель» (завершённые лоты) визуально идентичны активным по фону/оформлению — отличаются только бейджем. Добавить, например, приглушение фона/понижение elevation для завершённых карточек, чтобы разница считывалась боковым зрением.

### 2.6 Добавить текст с количеством найденных заявок над списком/пагинацией
Например: «Показано 3 из 3 заявок». Особенно важно после реализации фильтров (2.4), чтобы пользователь понимал объём результата.

### 2.7 Добавить иконки в бейджи статусов
Бейдж «На повышение» уже использует иконку-стрелку. Распространить паттерн на «Победитель» и нейтральный статус «Моей ставки нет» — иконка + цвет надёжнее считывается, чем только цвет (важно для контрастной чувствительности/дальтонизма).

### 2.8 Вынести цветовую палитру в MUI theme.palette
Цвета сейчас захардкожены по месту (видно по сгенерированным `css-xxxxx` классам в разных компонентах). Определить именованные токены в `theme.palette`: `background.default`, `background.paper` (см. 1.5), `primary.main/dark`, `success.main` (статус «На повышение»), `info.main` (статус «Победитель»), `divider`/`border`. Бейджи и кнопки должны брать цвет из темы, а не дублировать hex-значения.

## Приоритет 3 — низко (по возможности)

- **Иконка типа кузова** на карточке рядом с текстом (фургон/тентованный/бортовой) — для более быстрого сканирования списка.
- **Таймер/индикатор оставшегося времени** до дедлайна подачи ставки на карточке заявки.
- **Единый набор полей** для всех статусов карточки — у «Победителя» отсутствует «₽/км», хотя у активных лотов оно есть; показывать одинаковый набор полей (можно приглушённым цветом, если неактуально).
- **Иконка на кнопке «Сделать ставку»** (молоток/аукцион) для более быстрой визуальной идентификации главного действия.
- **Разделительная линия/контейнер** между заголовком + фильтрами и лентой карточек — сейчас они визуально не сгруппированы.
- **Плавное раскрытие панели фильтров** (`height`/`opacity transition` 150–250ms) вместо мгновенного появления.
- **Numeric badge на кнопке «Фильтры»**, когда хотя бы один фильтр активен.
- **Aria-label** на селекторе «количество на странице» («Количество элементов на странице»), если сейчас его нет.
- **Skeleton-состояния** при загрузке/смене страницы/фильтрации (актуально при подключении реального API).

## Проверка после внедрения

1. Контраст: любая новая пара фон/текст и фон/фон (карточка vs страница) — прогнать через WCAG contrast checker, текст ≥4.5:1 (уже выполняется), UI-границы ≥3:1.
2. Hover: вручную навести курсор на каждую интерактивную кнопку/карточку — должно быть заметное визуальное изменение.
3. Фильтры: применить фильтр по маршруту/датам, убедиться что список обновляется и есть способ сбросить.
4. Пагинация: визуально сравнить кнопку номера страницы и селектор размера страницы — не должны совпадать по стилю.
5. Адаптив: проверить весь список изменений при ширине 390px (мобильная) — ничего не должно ломаться/наезжать.
